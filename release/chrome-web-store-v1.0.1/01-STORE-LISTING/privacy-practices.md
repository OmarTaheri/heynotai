# Privacy practices — paste-ready dashboard answers

Every block below is written to be pasted verbatim into the matching field in
the Chrome Web Store **Privacy practices** tab. Each field allows 1000
characters; the counts in parentheses are the actual lengths.

Verified against the shipped code on August 15, 2026 (manifest permissions,
`entrypoints/background.ts`, `lib/auth-state.tsx`, `lib/scans-api.ts`,
`api/src/services/auth.ts`).

---

## Single purpose description

heynotai has one purpose: to tell you whether a specific piece of content you are looking at was likely generated by AI. You choose the content — highlight text, or open a supported video or post — and start a check with the toolbar button, the keyboard shortcut, a heynotai right-click menu item, or automatic checking on a platform you have turned on yourself. The extension sends that content to the heynotai detection API and shows the resulting AI-probability verdict in a drawer on the page.

Everything else serves that one job: sign-in identifies the account a check's quota and history belong to, settings control where checking is allowed, and the history view lists past results. The extension does not alter page content, insert ads, or use what it reads for anything other than returning a detection result to you.

---

## storage justification

Used only for `chrome.storage.local`, and only for data the user created by using the extension: their settings (which platforms automatic checking may run on, theme, normal/power UI mode, right-click and badge toggles, preferred detection model), the session issued by our own API so they are not asked to sign in again on every browser restart, and the most recent check results so the drawer and the on-page result badge can be restored after Chrome unloads the service worker.

Nothing else is written to storage — no browsing profile, no page contents beyond the most recent result, no third-party data. Storage is read only by the extension itself and is removed when the extension is uninstalled.

---

## activeTab justification

Used to act on the tab the user is looking at, at the moment they explicitly invoke heynotai: clicking the toolbar button, pressing the keyboard shortcut, or choosing a heynotai entry in the right-click menu.

That access is what lets the extension open its result drawer in that tab and read the one thing the user asked to check — the text they highlighted, or the URL and title of the video or post in view — and then show the verdict in place.

It is not used to inspect tabs the user has not invoked the extension on, and it grants nothing on its own until that user gesture happens.

---

## scripting justification

Used to inject the extension's own bundled content scripts into the current tab when they are not already running — after an install or update, or when Chrome has restarted the service worker and a finished verdict still has to be delivered to a page that was loaded before that.

Those scripts render the heynotai drawer and the on-page result badge, and read the content the user asked to check. They are static JavaScript files shipped inside the extension package and injected with `chrome.scripting.executeScript` using the `files` option. No code is downloaded, no code is assembled from strings, and `eval` and `new Function` are never used.

---

## identity justification

Used for a single call: `chrome.identity.launchWebAuthFlow`, to complete sign-in.

All credential entry happens on our own website (https://heynotai.com/extension-auth) — the extension never sees a password, a Google password, or a Google token. The flow returns a one-time code to the extension's `chromiumapp.org` redirect URL, and the extension exchanges that code with the heynotai API for a session token belonging to that account.

An account is required because detection models run on our servers: the account is what a user's check quota, saved history, and synced settings belong to. The permission is not used to read a Google profile directly or to obtain any Google API scope.

---

## contextMenus justification

Used to add heynotai's right-click entries, which are the main way users start a check on the content itself rather than hunting for a button.

There are two kinds: "AI check this text with heynotai", shown when text is selected, and one entry per supported surface — YouTube video and Short, Instagram post and reel, Facebook post and reel — each restricted by URL pattern so it appears only on that platform's matching pages.

Nothing happens unless the user clicks an entry; the click is the gesture that starts the check. If the user turns the right-click option off in settings, the entries are removed from Chrome entirely.

---

## Host permission justification

AI-generated content is not confined to a fixed list of sites. Users ask heynotai to check text on whatever they happen to be reading — a news article, a forum thread, a job listing, a school assignment, a blog — so the hosts cannot be enumerated in advance, and a narrower list would simply make the product fail on the pages people care about.

Broad host access is used for two things: rendering the heynotai drawer and result badge in the tab the user invoked, and reading the specific content they asked to check (the highlighted text, or the URL and title of a supported video or post).

Automatic checking is off by default and runs only on platforms the user explicitly enables. Content leaves the browser only for a check the user started or enabled, and only to the heynotai API. Nothing is collected for advertising, profiling, or resale.

## Remote code

Select **No, I am not using remote code.**

If a justification box is shown, paste:

All JavaScript and WebAssembly that heynotai executes is bundled in the extension package. The extension makes HTTPS requests to the heynotai API for authentication and detection results, but those responses are JSON data, never code. There are no remote script tags, no remote module imports, no `eval`, and no `new Function`; `chrome.scripting.executeScript` is called only with `files` that ship inside the package.

Note: the drawer stylesheet currently `@import`s the Inter and JetBrains Mono
webfonts from `fonts.googleapis.com`. Fonts and CSS are not remote code under
this policy, so the "No" answer stays correct — but it is a live request to
Google every time the drawer opens. `extension/public/fonts/README.md` already
recommends self-hosting the two woff2 files instead. Worth doing before or soon
after the first review.

## Data usage — what to check

Check these five:

| Data type | Why it applies |
| --- | --- |
| Personally identifiable information | The API returns the account's name, email address, and account ID, which the extension stores locally and shows in the Account tab. |
| Authentication information | The extension stores the API's access and refresh tokens in `chrome.storage.local` (no passwords — sign-in happens on the website). |
| Location | Only in the sense the form means it: the API records the IP address and user agent on each session record for security. No GPS, no geolocation API. |
| Web history | A check on a video or post sends that page's URL and title to the API, where it is saved as the user's check history. |
| Website content | The text the user highlights, and the media/page metadata of the item being checked, are sent to the API to be analyzed. |
| User activity | Defensible either way. The extension logs no clicks, scrolls, or keystrokes, but the API keeps a timestamped record of each check the user ran. Checking it is the safer disclosure. |

Leave unchecked: **Health information**, **Financial and payment information**
(billing happens on the website, never in the extension), and **Personal
communications** — the extension does not read mail or messages; it transmits
only text the user has deliberately highlighted, which is covered by Website
content.

Certify all three disclosures — none of them are violated: no data is sold or
transferred to third parties outside the approved use cases, none is used for
anything unrelated to AI detection, and none is used for creditworthiness or
lending.
